## Behavior implemented

All fourteen `/api/runner/v1` operations, split across two seams:

- `HttpPullProtocol: PullProtocol` — enroll, refresh, claim, heartbeat,
  accept + start (the two phases of `report_start`), completion,
  cancellation-observation, recovery-observation. Ten routes.
- `HttpPullProtocol: AttemptDataProtocol` — events, decisions,
  decisions/poll, artifact manifest, artifact content. Four routes plus the
  content PUT.
- `HttpRunnerClient: RunnerProtocolClient` — the daemon loop: establish a
  session, replay unresolved journal records, then claim/heartbeat until
  shutdown.

Decisions worth recording:

1. **`AttemptDataProtocol` is a second trait, not five more `PullProtocol`
   methods.** `engine.rs` is not owned by this card and has *no call site* for
   events, decisions or artifacts — a repo-wide read confirms the runner never
   submits an event batch, opens a decision or uploads an artifact today.
   Widening `PullProtocol` would have forced edits to unowned test fakes for
   methods nothing calls. The wiring request is below.
2. **The claim lease is built from both halves of the response.**
   `claim.response.json`'s `lease` object carries neither `attempt_number` nor
   `state`; both live on the sibling `attempt` snapshot. Deserializing
   `AttemptLease` straight from `lease` would have silently produced defaults
   and made `ClaimedWork::workspace_repository`'s redundancy check vacuous.
3. **The error code comes from the body, never the status line.**
   `stale_lease`, `conflict` and `idempotency_conflict` are all HTTP 409.
   Branching on status would collapse them — exactly the defect the card
   named. `every_frozen_error_fixture_maps_to_its_typed_variant` covers all
   fifteen codes and asserts the count, so a code added later cannot go
   unmapped silently.
4. **`Rejected` was narrowed, not reused as a catch-all.** It now means "the
   server refused, but the body was not a parseable v1 envelope" — a real,
   distinguishable condition (a proxy, a non-v1 server) that must not be
   reported as one of the fifteen contract codes.
5. **Retry needs two independent conditions:** the code is retryable
   (delegated to `StableErrorCode::retryable`, i.e. to `errors/*.json`) *and*
   the operation is replayable by construction. Enrollment fails the second
   test — its token is single-use, so a lost response is ambiguous and a
   resend would burn a token without recovering the credential. Artifact
   content upload also never retries: content is immutable once verified, so
   a resend after an ambiguous first send returns `conflict` and would mask a
   success.
6. **The client owns the base path.** `protocol.json` fixes
   `base_path: /api/runner/v1`, so `--api-url http://host:3210` and
   `--api-url http://host:3210/api/runner/v1` both work. This was found by
   the gate: `scripts/smoke.sh` passes the server origin, and the first
   implementation posted to `/enroll` at the root.
7. **The artifact upload URL is the server's grant, not a reconstruction.**
   `artifact.response.json` records `upload.method`/`upload.path` as data. Its
   example path (`/artifacts/{id}/content`) differs from the mounted route
   (`/attempts/{attempt_id}/artifacts/{id}/content`), and the server returns
   the mounted one. Following the grant makes the client correct under both —
   **but the fixture's example path is stale and should be corrected by the
   fixture's owner** (see escalations).
8. **The session is persisted** (`state_dir/session.json`, mode 0600, written
   via temp-file + rename). Without it a restarted runner would need a fresh
   operator-issued enrollment token every time. A persisted session is
   validated with a non-rotating `refresh` before it is trusted; the
   enrollment token is spent only if the server refuses it.
9. **Idle heartbeats are the daemon's job.** The engine heartbeats only for
   attempts it is running; `select.rs`'s `max_heartbeat_age` (60s) excludes a
   runner that never heartbeats, so an idle runner that only long-polled
   `/claim` would have gone stale and never been scheduled.
10. **Capability claims are conservative on purpose.** The enrollment snapshot
    reports `decisions: unsupported` and `artifacts: unsupported` with reasons,
    because the wire operations exist but the engine has no call site for
    them. `cancel` reports `PROCESS_GROUP_CANCEL_CEILING` (advisory), not
    `supported`.

## Failure/adversarial case proved

- **The gate is load-bearing.** `git stash -u` (reverting only this card) and
  re-running `./scripts/smoke.sh` fails at step 6 with the exact recorded P0:
  `tack-runner: runner protocol client is not configured`, exit 1. Restoring
  the change makes it pass. Recorded, not assumed.
- **`stale_lease` never arrives as a generic conflict**
  (`a_stale_lease_never_arrives_as_a_generic_conflict`) — the assertion
  includes an `assert_ne!` against `Protocol { code: Conflict }`, so the test
  fails if the mapping ever regresses to status-line branching.
- **Enrollment is never resent** even when the failure *is* retryable by code
  (`enrollment_is_never_resent_even_when_the_failure_is_retryable`): the mock
  returns the retryable `internal_error` fixture, and the test asserts the
  server saw exactly **one** request.
- **Absence asserted directly, not via a status code:**
  `reporting_running_without_a_process_id_is_typed_not_sent` asserts the mock
  recorded **zero** requests — the invalid report never reached the wire.
- **Bounded retry:** `a_retryable_code_is_resent_only_up_to_the_bound` asserts
  exactly 3 sends for `max_attempts: 3`;
  `a_non_retryable_code_is_sent_exactly_once` asserts exactly 1.

Live verification against a real `tack serve` (evidence, not a CI test):
enrolled as `runr_2ac5fc46-…`, `state: active`, real `labels`
(`{"arch":"x86_64","os":"linux"}`), real capability snapshot, and
`last_heartbeat_at` advancing to `2026-08-19T17:36:47Z` — i.e. idle heartbeats
are landing, not merely a successful enrollment. A restart with a deliberately
invalid `--enrollment-token` logged `runner session resumed` with the **same**
runner id and created no second runner row: the persisted session was used and
no token was spent.

## Known limitations or `not_measured` fields

- **A claimed attempt still cannot execute.** `UnavailableWorktreeProvisioner`
  remains the only `WorktreeProvisioner` in the tree and refuses every
  provision with a typed `WorkspaceError::WorktreeUnavailable`. The Wave 7
  board states the transport was "the only missing piece" — **that is not
  correct, and this card cannot fix it inside its ownership** (`workspace.rs`
  is not in `Owns`). The runner now enrolls, claims, heartbeats and reports,
  but a claimed attempt fails at provisioning. **III-H2's steps 7–9 cannot
  produce evidence until a real git worktree provisioner lands.** This is the
  next card; it is small (one `WorktreeProvisioner` impl) but it is real.
- **Artifact content is buffered in memory** (bounded by the contract's 50 MB
  `artifact_content_bytes_max`). Streaming would need `reqwest`'s `stream`
  feature on the shared workspace dependency table.
- Adapter and probe are separate boxed instances (`register_adapter` and
  `register_probe` each take ownership), so the adapter's version cache is not
  the probe's and `wait()` falls back to a one-off detection — documented
  adapter behaviour, never a fabricated version.
- **`scripts/smoke.sh` leaks server processes** (III-H2's file, not edited):
  the server is started in a subshell and `cleanup` kills the subshell, not
  the `tack` child, so an orphan keeps port 3399 and a *later* run silently
  talks to the *previous* run's database. This produced a spurious step-5
  failure ("Runner name already exists") twice during this card before it was
  diagnosed. Requested fix for III-H2: capture the child pid, or `kill -- -$$`
  the process group.

## Secrets/logging review

- The enrollment token appears only in the enrollment request body
  (`protocol.json`: `single_use_enrollment_token_in_request_body`); the test
  asserts no `Authorization` header is sent on that call.
- The runner credential appears only in an `Authorization: Bearer` header.
  `the_bearer_header_is_the_only_place_a_credential_is_written` asserts it is
  absent from the body and the path.
- `reqwest`'s error is **dropped, never wrapped**: its `Display` carries the
  request URL and can carry a source chain. `RunnerError::ProtocolTransport`
  is deliberately detail-free because `main` prints it.
- `secrets_never_appear_in_logs_or_errors` asserts redaction across
  `RunnerSession`, `RunnerCredential`, `EnrollmentCredential` and every
  `ProtocolClientError` variant.
- `session.json` holds a live credential and is written mode 0600;
  `a_persisted_session_round_trips_and_is_owner_only` asserts the mode.
- Live-run logs were grepped for the actual issued credential: clean in
  `runner.log`, `restart.log` and the server's own log.

## `unavailable_protocol_is_a_typed_failure_not_success`

**Updated, not retired**, with the reason recorded in the test's own doc
comment. It was written to pin this card's P0; that gap is closed and
`main.rs` no longer uses `UnavailableProtocolClient`. The type still exists and
is still reachable by any future composition that omits a transport, and the
assertion's remaining value is that such a composition fails as a typed
`ProtocolUnavailable` rather than reporting success and idling forever.
Deleting it would remove the only guard on that fallback's honesty; what
changed is what the test *means*.
